## 2026-10-18 — タブの切り替えを速く・新しい版への自動更新
- 計測：Vercel の関数はすでに東京（`kix1::hnd1`）、Supabase も日本から約 0.1 秒で応答。地域の問題ではなかった。一方、サーバーの応答は 0.2〜2.6 秒とばらつき、遅いものはコールドスタート（休止からの起動）。
- 原因：アプリ共通の枠 `(app)/layout.tsx` が毎回サーバーでログイン確認・プロフィール・減量計画を読んでいたため、全タブが「動的」になり、タブを押すたびにサーバー（起動待ちを含む）を待っていた。先読みも効かなかった。
- 対策：プロフィールと減量計画は端末で読む形に（`AppDataProvider` が TanStack Query で取得し、保存済みキャッシュから即表示、画面移動のたびに裏で更新。端末のセッションと一致したデータだけ表示）。枠はサーバーで何も読まないので、ホーム・トレ・食事・コンディション・分析・体重・減量フェーズ・アルバムが静的ページになり、CDN から配信・先読みされる。ログインの保護は従来どおりミドルウェア（未ログインは /login へ転送、確認済み）。
- ミドルウェアの確認を `getUser`（毎回 Supabase に問い合わせ）から `getClaims`（可能なら端末内で検証）に変更。
- 設定・レポートなどサーバーを使う画面には読み込み中の表示（`loading.tsx`）。`router.refresh()` はアプリデータの再読み込みに置き換え。
- 新しい版を出したとき、スマホが古い版のまま動き続ける問題に対応：アプリを前面に戻したときに更新を確認し、新しい版に切り替わったら 1 回だけ自動で再読み込み（`UpdateWatcher`）。
- DB 変更なし。
