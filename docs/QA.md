# モバイル実機での確認項目

自動テスト（Vitest / Playwright）はログイン前の画面とロジックまで。ログイン後の流れは実機で確認する。
対象：iPhone（Safari、ホーム画面に追加した PWA）と Android（Chrome、インストールした PWA）。幅 375px 前後。

## 共通
- [ ] 画面上部がノッチ／ステータスバーに潜らない（ヘッダー・オンボーディング・ログイン）
- [ ] 下タブがホームバーに潜らない。タブのタップ領域が十分（48px 以上）
- [ ] 数字が Barlow Condensed で表示される（体重・セット表・PFC）
- [ ] 赤い表示がどこにも出ない（悪い値・超過はアンバー）
- [ ] 機内モードにして各タブを開ける（前回表示した内容が出る）

## 認証・オンボーディング
- [ ] メールのコードでログインできる（PWA 内で完結する）
- [ ] メールのリンクでもログインできる（同じ端末のブラウザ）
- [ ] 銘を切る → 身体 → プレップ設定 →「研ぎ始める」でホームに着く。途中で閉じても続きから再開できる
- [ ] プレップ設定の週ペースと予測ラインが入力に追従する。届かない場合はアンバーの一文が出る

## コンディション・ホーム
- [ ] 朝のチェックインが 30 秒以内で終わる。記録後ホームに戻り、すぐ反映される
- [ ] 機内モードで記録 → ヘッダーに「未送信 1」→ 電波を戻すと消え、別端末でも見える
- [ ] 週平均が大きく、今朝の体重が小さく表示される。30 日チャートの点・実線・点線目標
- [ ] 3 日続けて体調を低めに入れると「なぜやるのか」が出る（基準に 7 日以上の記録が必要）

## トレーニング
- [ ] ルーティン作成（曜日つき）→ トレタブとホームに「今日」として出る
- [ ] ワークアウト中に前回値がゴースト表示される。空欄のまま ✓ で前回値で確定
- [ ] ✓ でレストタイマーが始まり、終了時に振動・通知（通知許可後）。+30s／スキップ
- [ ] 画面ロック中のレスト終了通知（Android の PWA。iOS は制限あり、下記）
- [ ] ワークアウト中にアプリを閉じて開き直しても入力が残る
- [ ] 完了サマリーの総ボリューム・セット・PR が正しい。今日の感触を保存できる
- [ ] 重量ステッパー（±0.25 / ±2.5）と回数 ±1 が現在のセットに効く

## 食事
- [ ] 食品検索 → テンキーでグラム → 追加。選択中の食事枠に入る
- [ ] マイ定食をタップで 1 タップ記録できる
- [ ] 「残りを埋める」の候補が出て、追加すると残りが減る
- [ ] トレ日／オフ日の切替で目標が変わる
- [ ] 機内モードで記録 → 再接続で送信される

## 分析・設定
- [ ] 12 週トレンド、主観ヒートマップ（7 日）、筋群別セット数の人体図
- [ ] CSV（トレ・食事・チェックイン）がダウンロードでき、Excel で文字化けしない
- [ ] ログアウトで未送信がある場合に警告が出る

## PWA
- [ ] ホーム画面に追加でき、アイコン（焼き入れの「研」）とスタンドアロン表示になる
- [ ] 2 回目以降の起動が速い（Service Worker のキャッシュ）

## 既知の制限
- iOS のホーム画面 PWA は、アプリがバックグラウンドの間タイマーが止まりやすく、レスト終了通知が届かないことがある。確実なロック画面通知には Web Push（プッシュサーバー）が必要で、MVP の範囲外
- Supabase 標準のメール送信は 1 時間あたりの通数と送信先が制限される。公開前にカスタム SMTP（Resend など）を設定する
